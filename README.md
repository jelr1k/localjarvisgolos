# JARVIS — локальный настольный ассистент

JARVIS — настольный ассистент для Windows 11. Он объединяет локальную языковую модель через Ollama, текстовый чат, инструменты для работы с файлами и приложениями, голосовой ввод и систему обновления через GitHub Releases.

**Текущая версия в исходниках:** `0.1.0`  
**Основной стек:** Python, PySide6, Ollama, faster-whisper, Vosk, Piper TTS.  
**Хранилище исходников:** [jelr1k/localjarvisgolos](https://github.com/jelr1k/localjarvisgolos).

## Что уже реализовано

### Чат и языковая модель

- Потоковая генерация ответов через локальную модель Ollama.
- Переключатель режима размышления для отдельного запроса.
- `Command Router`: простые однозначные команды обрабатываются без LLM.
- `Tool Calling` для сложных и составных запросов: модель может последовательно вызывать разрешённые инструменты и получать результаты их выполнения. Ограничение — до пяти раундов вызова инструментов на одну генерацию.
- Для каждого запроса формируется ограниченный набор доступных инструментов, а `ToolExecutor` повторно проверяет разрешения перед выполнением.
- История текущего диалога, обработка подтверждений и потоковый вывод ответа.
- Статистика последней генерации: токены, длительность, скорость, время до первого токена и параметры размышления.

### Файлы и Workspace

Файловые инструменты работают с реальными объектами рабочего каталога `workspace/`. Доступны:

- поиск и чтение файлов;
- создание файлов и папок;
- запись и перезапись содержимого;
- удаление, переименование, копирование и перемещение файлов;
- получение информации об объекте.

Вкладка **Workspace** позволяет просматривать рабочие файлы, добавлять файл через диалог выбора или перетаскиванием из Проводника, а также редактировать алиасы.

`WorkspaceIndex` индексирует реальное содержимое рабочего каталога. Поиск поддерживает нормализацию имён, базовые автоматические и пользовательские алиасы, нечёткое сопоставление и обработку неоднозначных совпадений.

### Безопасность инструментов

- Файловые пути проверяются через отдельную песочницу (`sandbox`); путь, который разрешается за пределами `workspace/`, блокируется.
- Не используются произвольные команды CMD, PowerShell или shell как универсальный способ выполнения действий.
- Разрешения инструментов можно включать и отключать во вкладке **Инструменты**.
- Запись, перезапись, удаление, переименование, копирование и перемещение файлов требуют подтверждения.
- Запуск приложений отделён от файловых операций. В настройках есть отдельный переключатель, разрешающий открытие приложений за пределами Workspace.

Эти ограничения относятся к встроенным инструментам JARVIS. Они не заменяют общую безопасность Windows и не означают, что все возможные действия с компьютером доступны ассистенту.

### Управление приложениями

JARVIS умеет искать установленные приложения, проверять состояние процессов, запускать приложения и поддерживаемые объекты Workspace, сворачивать и закрывать приложения, а также открывать HTTP/HTTPS-ссылки. Запуск использует системные механизмы Windows и не строится на выполнении произвольных shell-команд.

### Голосовой ввод и wake word

- Локальное распознавание речи через `faster-whisper`.
- Обнаружение ключевой фразы через Vosk; по умолчанию используется `Jarvis`. Wake word можно отключить и изменить в настройках.
- Запись с выбранного микрофона и автоматическое завершение записи после обнаружения тишины.
- Ленивая загрузка модели Whisper при первом распознавании.
- Нормализация частых голосовых вариантов пунктуации и расширений файлов.
- Распознанный текст поступает в тот же путь обработки сообщений, что и текстовый ввод: Command Router → при необходимости LLM и разрешённые инструменты.
- В настройках доступны модель Whisper (`small`, `medium`, `large-v3` или локальная модель), число CPU-потоков, beam size, VAD, таймкоды, использование предыдущего текста, микрофон и порог тишины.
- Статистика распознавания показывает время подготовки аудио, загрузки модели и транскрибации, параметры запуска и real-time factor.

Whisper и модель Ollama выполняют разные задачи: Whisper преобразует речь в текст, а Ollama используется для генерации ответов и обработки сложных запросов.

### Синтез речи (TTS)

- Локальная генерация речи через Piper TTS. Текст не отправляется в облачный сервис озвучивания.
- Отдельная очередь и рабочий поток: синтез и воспроизведение не блокируют интерфейс.
- Один канал озвучивания для готовых ответов ассистента и шуточных реплик RoflService; промежуточные токены и сообщения о ходе фоновой работы не читаются вслух.
- В настройках можно отключить автоматическую озвучку, выбрать один из поддерживаемых русских голосов, настроить скорость/громкость, скачать модель и проверить тестовую фразу.
- Модель голоса скачивается по запросу пользователя один раз и хранится отдельно в пользовательском каталоге. Автоматическая озвучка по умолчанию отключена.
- Wake word временно игнорирует входящий звук во время воспроизведения, чтобы динамик не запускал ассистента сам на себя.

Подробное описание компонентов, событий и потока запросов: [архитектура TTS](docs/02_ARCHITECTURE/TTS_ARCHITECTURE.md). Piper распространяется под GPL-3.0-or-later; перед упаковкой в распространяемый закрытый EXE нужно отдельно проверить лицензионные требования. Лицензия каждой голосовой модели также проверяется отдельно.

### Интерфейс

Основное окно содержит вкладки:

- **Чат** — общение с ассистентом и голосовой ввод.
- **Генерация** — статистика LLM/Whisper и состояние ресурсов системы.
- **Настройки** — модель, параметры генерации, микрофон, голосовой ввод, Ollama, обновления и другие параметры.
- **Алиасы** — управление пользовательскими именами объектов.
- **Workspace** — просмотр и добавление файлов, редактирование алиасов.
- **Инструменты** — разрешения для отдельных инструментов.
- **Ollama** — состояние сервера, загрузка и выгрузка модели.

Также есть отдельное окно со справочником команд Command Router.

### Настройки и рофлы

- Имя ассистента, используемая модель Ollama, температура, размер контекста и максимум токенов ответа.
- Настройки локального голосового распознавания и выбора микрофона.
- Адрес Ollama Server и тестовый режим только с Command Router, без LLM.
- Вероятностные шуточные реакции на некоторые действия, включая отдельные «демонические» реплики. Вероятности настраиваются в служебном окне настроек рофлов.

## Проверка и установка обновлений

В приложении есть система обновления через **GitHub Releases**:

- проверка обновлений вручную из настроек и фоновая периодическая проверка;
- сравнение версии приложения с опубликованными релизами;
- подтверждение пользователя перед скачиванием;
- загрузка ZIP-архива, проверка архива и его безопасных путей;
- создание резервной копии текущей установки;
- запуск отдельного процесса обновления, чтобы не заменять файлы работающего приложения;
- установка обновления и повторный запуск JARVIS;
- попытка отката к резервной копии, если установка завершается ошибкой.

При обновлении предусмотрено сохранение пользовательских настроек, Workspace, журналов и кэшей моделей Ollama/Hugging Face. Журнал процесса обновления пишется в `logs/updater.log`.

В репозитории также есть GitHub Actions workflow для ручной публикации ZIP-релиза. **Финальная автономная сборка `.exe` и её проверка ещё не завершены**; текущее описание обновления относится к исходной конфигурации проекта.

## Где хранятся данные

Расположение приложения определяется автоматически, а не привязано к фиксированному пути вроде `C:\\JARVIS`.

- `workspace/` — рабочие файлы, доступные встроенным файловым инструментам.
- `logs/` — журналы диагностики.
- `%APPDATA%\\Jarvis\\settings.json` — пользовательские настройки.
- `%APPDATA%\\Jarvis\\aliases.json` — пользовательские алиасы.

В режиме исходников корнем считается корень проекта. В собранном приложении корнем должен быть каталог рядом с запущенным исполняемым файлом.

### Журналирование

Журналы разделены по подсистемам: общие сообщения, ошибки, запуск, фатальные ошибки, события, голосовой ввод, команды и инструменты, Ollama/LLM, загрузка зависимостей и updater. При обычном запуске через bootstrap прежние файлы `*.log*` в каталоге `logs/` очищаются намеренно, после чего журналы создаются заново.

## Запуск из исходников

Требуется Windows 11, Python и установленная отдельно Ollama. Для запуска LLM-режима в Ollama должна быть доступна хотя бы одна подходящая модель. Python 3.12 рекомендуется для воспроизводимой настройки окружения; в документации проекта указана поддержка Python 3.11+.

Из корня репозитория в CMD:

```bat
py -3.12 -m venv .venv
.venv\Scripts\activate
python -m pip install --upgrade pip
python -m pip install -r config\requirements.txt
python start\bootstrap.py
```

Для обычного запуска можно использовать `start.bat`: он проверяет/устанавливает Python-зависимости и запускает bootstrap без консольного окна. Для корректного использования виртуального окружения запускайте его из CMD, где окружение уже активировано.

Установка зависимостей через `pip` не устанавливает саму Ollama и не загружает автоматически модель LLM. Whisper-модель может быть подготовлена через настройки приложения; при первом использовании ей может потребоваться загрузка.

## Запуск тестов

Из активированного виртуального окружения в корне проекта:

```bat
python -m pytest -q
```

Для части функций есть unit-, regression- и интеграционные тесты, включая песочницу, файловые инструменты, Command Router, голосовые подсистемы и этапы обновления. Это не является гарантией отсутствия ошибок во всех конфигурациях Windows или при финальной сборке.

## Структура проекта

- `core/` — жизненный цикл приложения, конфигурация, пути, события, задачи и управление Ollama.
- `llm/` — интерфейс провайдера, запросы к LLM, потоковые ответы и статистика.
- `chat/` — сообщения и история текущего диалога.
- `services/` — чат, маршрутизация и сервисы обновления.
- `tools/` — реестр инструментов, файловые операции и работа с приложениями.
- `security/` — разрешения, проверка аргументов и файловая песочница.
- `voice/` — запись с микрофона, Whisper, wake word, настройка устройств и нормализация голосовых команд.
- `presentation/` — контроллеры между backend и PySide6-интерфейсом.
- `ui/` — страницы и окна приложения.
- `start/` — bootstrap, точка входа, установка зависимостей и отдельный updater.
- `config/` — список Python-зависимостей и конфигурационные шаблоны.
- `tests/` — тесты.
- `docs/` — техническое задание, архитектура, требования установки и справочник команд.

## Что пока не реализовано

- Полноценная проверенная автономная сборка и установщик `.exe`.
- Синтез речи (TTS) для ответов JARVIS.
- Автоматический выбор LLM-модели по сложности задачи (Model Router).
- Выполнение произвольных команд CMD/PowerShell как отдельный контролируемый инструмент.

Справочник команд и подробные технические материалы находятся в каталоге `docs/`. Описание возможностей выше отражает реализацию исходников, а не все идеи из дорожной карты.
