# JARVIS

Локальный настольный ассистент для Windows 11 на Python + PySide6 + Ollama. Проект рассчитан на постепенное расширение: текстовый чат → инструменты → роутер команд → голосовое управление и сборка в `.exe`.

## Что уже реализовано

- потоковый чат с локальной моделью Ollama;
- отдельный слой LLM и сервисов;
- прямой Command Router для однозначных команд без LLM;
- централизованный `ToolExecutor` с повторной проверкой разрешений;
- файловые инструменты: поиск, чтение, создание, запись, удаление, переименование, копирование, перемещение, создание папок и информация о файлах;
- поиск установленных Windows-приложений и проверка процессов;
- запуск приложений без shell-команд;
- подтверждение опасных действий;
- фактическая проверка результата удаления/перемещения/копирования;
- журналирование в `logs/jarvis.log`;
- отдельная страница управления Ollama Server и текущей моделью;
- автоматическое определение корня приложения;
- sandbox без жёсткой привязки к `C:\JARVIS`;
- пользовательские настройки в `%APPDATA%\Jarvis\settings.json`.

## Автоматическое определение пути

Jarvis не содержит абсолютного пути к месту установки.

В режиме исходников корнем считается корень проекта, определённый относительно исходного модуля. В собранном приложении корнем считается каталог, в котором находится реально запущенный `Jarvis.exe`.

Поэтому проект можно перенести, например:

```text
C:\Jarvis
→
D:\Apps\Jarvis
```

без изменения кода и конфигурации. Рабочая папка будет находиться рядом с текущей установкой:

```text
Jarvis/
├── Jarvis.exe       # в будущем
├── workspace/       # файловый sandbox
├── logs/
├── resources/
└── ...
```

Настройки пользователя не зависят от этого расположения и хранятся в `%APPDATA%\Jarvis\settings.json`.

## Sandbox

Все файловые инструменты работают только внутри `workspace`.

Проверяется нормализованный путь с учётом:

- `..`;
- абсолютных путей;
- разных разделителей Windows;
- symlink;
- junction/reparse point;
- другого диска.

Путь вне workspace блокируется до выполнения операции.

Произвольные `cmd`/PowerShell/shell-команды не используются.

## Ollama

Jarvis может:

- проверить состояние сервера;
- запустить Ollama Server;
- остановить сервер, если он был запущен самим Jarvis;
- загрузить текущую модель;
- выгрузить текущую модель;
- показывать отдельное состояние сервера и модели.

При закрытии окна Jarvis модель освобождается, а уже запущенный Ollama Server остаётся работать.

## Запуск из исходников

Требуется Python 3.11+.

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python main.py
```

`start.bat` уже переключает рабочий каталог на папку самого скрипта, поэтому перенос проекта не требует изменения команды запуска.

## Архитектура

```text
Ввод
 ↓
Command Router
 ├─ простая команда → ToolExecutor
 └─ сложная команда → Ollama/LLM → ToolExecutor
                         ↓
                    sandbox/permissions
                         ↓
                    реальное действие
                         ↓
                    проверка результата
```

Основные каталоги:

- `core/` — жизненный цикл приложения, конфигурация, Ollama, пути, логирование;
- `llm/` — связь с языковой моделью;
- `services/` — чат и маршрутизация;
- `tools/` — инструменты и их реестр;
- `security/` — sandbox, валидация и разрешения;
- `ui/` — интерфейс;
- `tests/` — тесты безопасности и файловых операций;
- `docs/TZ_JARVIS.md` — полное техническое задание.
