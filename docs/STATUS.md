# Статус разработки Jarvis

**Дата обновления:** 2026-09-15  
**Ветка:** `osnova`  
**Связанный документ:** `docs/TZ_JARVIS.md`

Этот документ фиксирует фактическое состояние реализации ветки `osnova`.

## 1. Command Router — реализовано

Пользовательские сообщения проходят через Command Router до обращения к LLM. Простые однозначные команды могут выполняться напрямую через инструменты.

Для составных задач Router формирует набор необходимых tools и передаёт задачу в LLM Tool Calling.

## 2. Разделение обычного чата и tools — реализовано

Обычный разговор не получает весь набор инструментов. Для конкретной задачи формируется ограниченный scope tools, что снижает вероятность случайного вызова файловых или системных операций.

## 3. Tool Calling — реализовано

Поддерживается последовательная цепочка:

```text
Пользователь
    ↓
Command Router
    ↓
LLM + разрешённые tools
    ↓
tool call
    ↓
ToolExecutor
    ↓
результат
    ↓
следующий tool call / финальный ответ
```

`GenerationWorker` ограничивает последовательность пятью раундами.

## 4. Безопасность — реализовано

Сохраняются проверки разрешений, sandbox и подтверждения опасных операций. `ToolExecutor` не должен выполнять инструмент, который не входит в разрешённый scope текущего запроса.

## 5. Работа с файлами — реализовано, но есть известный баг

Файловые операции работают внутри разрешённого `Workspace`, однако текущая проверка показала несогласованность между отдельными сценариями.

Воспроизведённый сценарий:

```text
создать test.txt
→ файл создан

открыть test.txt
→ файл успешно открыт

что находится в test.txt
→ Jarvis сообщает, что файла не существует
```

Это означает, что разные пути обработки файловой команды могут использовать несовместимое разрешение имени. Кроме того, при голосовом вводе Whisper может превратить `test.txt` в `test.exe` или другую форму имени.

Требования к исправлению описаны в `docs/BUG_VOICE_FILE_NAME_RESOLUTION.md`.

## 6. Локальный голосовой ввод — реализовано частично

Сейчас используется `faster-whisper` локально. Текущая реализация `voice/speech_recognizer.py` использует:

- модель `small`;
- `device="cpu"`;
- `compute_type="int8"`;
- язык `ru`;
- целевую частоту 16 kHz;
- `beam_size=5`;
- `vad_filter=True`;
- ленивую загрузку модели при первом распознавании;
- автоматический ресэмплинг входного аудио к 16 kHz.

После распознавания текст передаётся в существующий путь обработки команд. Whisper не должен самостоятельно определять, существует ли файл.

Wake word, постоянное ожидание и TTS пока не реализованы.

## 7. Известная проблема сетевого окружения Whisper

В окружении пользователя локальный прокси Happ может приводить к тому, что Python/Hugging Face получает `socks4://127.0.0.1:10808`. Это вызывает ошибку `Unknown scheme for proxy URL`. Для диагностики проверено временное отключение proxy-переменных в текущей CMD-сессии. Данная проблема не является ошибкой модели Whisper.

## 8. Логирование — реализовано

В проекте присутствует расширенное диагностическое логирование маршрутизации, инструментов, LLM/Ollama и управления процессами.

## 9. Тесты — реализовано

В проекте есть unit/regression-тесты ключевых компонентов и GitHub Actions workflow для автоматического запуска тестов.
