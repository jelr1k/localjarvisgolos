# Система логирования Jarvis

## Назначение

Jarvis использует раздельные журналы для диагностики запуска, голосового ввода, Ollama/LLM, команд и общих ошибок.

Логи создаются локально в каталоге `logs/` рядом с Jarvis. Каталог логов не попадает в Git.

## Жизненный цикл логов

Логи являются журналом **текущего запуска Jarvis**.

При каждом новом запуске `start/bootstrap.py` сначала удаляет старые `*.log*` файлы, включая резервные копии от старой системы ротации. После этого создаются чистые файлы для новой сессии.

При обычном закрытии Jarvis текущие логи не удаляются. Поэтому после завершения приложения их можно спокойно открыть и разобрать.

Следующий запуск очистит их и начнёт новую сессию.

Если старый лог временно заблокирован другим процессом, его удаление пропускается, чтобы проблема с логом не мешала запуску Jarvis.

## Файлы

### `logs/jarvis.log`

Общий журнал самого приложения.

Сюда попадают сообщения верхнего уровня, например:

- запуск и завершение Jarvis;
- инициализация приложения;
- загрузка конфигурации;
- создание основных компонентов;
- общие события, для которых нет отдельной подсистемы.

Подробные сообщения голоса, команд и Ollama сюда больше не дублируются.

### `logs/errors.log`

Общий журнал ошибок уровня `ERROR` и выше.

Ошибки из специализированных журналов одновременно попадают сюда, поэтому этот файл остаётся единой точкой для поиска сбоев.

### `logs/startup.log`

Ранний запуск из `start/bootstrap.py`.

Используется для проблем, которые происходят до полноценной инициализации системы логирования Jarvis.

### `logs/fatal.log`

Данные `faulthandler` для фатальных ошибок Python, включая информацию по потокам.

### `logs/events.log`

Структурированные JSON-события по одной записи на строку.

Этот файл предназначен для событий, которые нужно удобно анализировать программно.

### `logs/voice.log`

Вся техническая информация голосовой подсистемы:

- микрофон и аудиопоток;
- Vosk/wake word;
- Whisper;
- запуск и остановка записи;
- распознанный текст;
- ошибки голосового ввода.

### `logs/ollama.log`

Всё, что относится к Ollama и LLM:

- состояние сервера Ollama;
- запуск и остановка Ollama;
- список и состояние моделей;
- загрузка и выгрузка моделей;
- запросы к Ollama;
- потоковые ответы;
- статистика генерации;
- ошибки LLM/Ollama.

### `logs/commands.log`

Обработка команд и инструментов:

- Command Router;
- сообщения ChatService;
- вызовы инструментов;
- подтверждения действий;
- поиск и разрешение целей;
- запуск, сворачивание и закрытие приложений;
- поиск процессов и дерево процессов;
- результаты выполнения команд.

## Откуда физически берутся записи

Логирование построено через именованные логгеры Python. Например:

- `jarvis.application` → `jarvis.log`;
- `jarvis.voice.*` → `voice.log`;
- `jarvis.ollama` и `jarvis.llm.*` → `ollama.log`;
- `jarvis.chat`, `jarvis.router`, `jarvis.tools`, `jarvis.process`, `jarvis.target_resolver` → `commands.log`.

Ошибки из этих подсистем дополнительно записываются в `errors.log`.

Это сделано через иерархию логгеров: например, `jarvis.voice.wake_word` является дочерним логгером `jarvis.voice`, поэтому ему не требуется отдельная настройка файла. Прекращение дальнейшего распространения после специализированного логгера также предотвращает повторную запись в `jarvis.log`.

## Ограничение размера

Файлы логов больше не ротируются и не создают цепочку резервных копий.

Ограничение размера теперь определяется одним запуском Jarvis: при следующем запуске старые логи удаляются.

Это специально сделано для текущего режима разработки: после завершения приложения диагностические данные остаются доступными, но история старых запусков не накапливается бесконечно.

## Важное замечание

Подробные журналы могут содержать текст команд, аргументы инструментов, содержимое LLM-запросов и сведения о процессах Windows. Это диагностические данные локального Jarvis, а не пользовательский журнал для публикации.
