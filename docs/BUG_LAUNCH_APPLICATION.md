# Баг: `launch_application` открывает не все файлы из `Workspace`

## Статус

**Исправлено в ветке `osnova`.**

## Описание

Jarvis должен уметь открывать файлы и ярлыки, находящиеся в его рабочей папке `Workspace`, по пользовательскому имени без обязательного указания расширения.

Исправлена логика, при которой при наличии нескольких реальных совпадений Jarvis мог сообщать только об общей неоднозначности. Теперь при реальной неоднозначности он показывает точные пути файлов и ожидает выбор пользователя.

Пример:

```text
Workspace/
├── Steam.lnk
└── Steam.exe
```

Команда:

```text
Запусти Steam
```

Jarvis показывает:

```text
Найдено несколько файлов с таким именем. Какой запустить?
1. Workspace/Steam.exe
2. Workspace/Steam.lnk

Введите номер варианта.
```

После ответа `1` или `2` запускается именно выбранный файл. При наличии ровно одного совпадения выбор не требуется.

## Требуемое поведение

`launch_application()` должен корректно открывать **любой разрешённый файл**, находящийся внутри `Workspace`, если пользователь однозначно указал его имя.

Минимально должны поддерживаться:

- `.lnk`;
- `.url`;
- `.exe`;
- `.bat`;
- `.cmd`;
- `.txt`;
- `.pdf`;
- другие файлы, которые Windows может открыть через зарегистрированное приложение.

Расширение не должно быть обязательным в пользовательской команде.

## Поведение при неоднозначности

Если в разрешённом `Workspace` найдено несколько реальных файлов, соответствующих одному имени, Jarvis не выбирает файл автоматически.

Он должен:

1. показать все найденные пути с номерами;
2. сохранить список вариантов до следующего ответа пользователя;
3. принять номер варианта, включая формы `1`, `2`, `первый`, `второй` и т. п.;
4. запустить ровно соответствующий выбранному номеру файл;
5. при неверном номере сохранить список и сообщить допустимый диапазон.

После успешного выбора ожидающий список очищается, поэтому следующий числовой ответ не может случайно повторно запустить старый вариант.

## Важное ограничение безопасности

Поиск файлов для запуска должен оставаться ограниченным `Workspace`.

Нельзя исправлять баг путём разрешения произвольных путей за пределами sandbox.

## Разделение источников поиска

`launch_application()` сначала проверяет `Workspace` через `resolve_tool_path()`.

Если найдено ровно одно совпадение, оно сразу запускается. Поиск установленных приложений Windows в этом случае не выполняется.

Если найдено несколько совпадений в `Workspace`, пользователь получает список именно этих файлов и может выбрать конкретный путь по номеру.

Только если в `Workspace` совпадений нет, выполняется поиск установленного приложения через `find_application()`.

## Ярлыки Windows

`.lnk` и `.url` остаются самостоятельными запускаемыми файлами. Для `.lnk` не требуется, чтобы имя ярлыка совпадало с именем реального `.exe`, поскольку запуск выполняется через `os.startfile()`.

## Критерии готовности

- [x] любой поддерживаемый файл из `Workspace` можно открыть по имени без расширения;
- [x] единственный найденный файл запускается без сообщения о нескольких вариантах;
- [x] `.lnk` корректно открывается как ярлык Windows;
- [x] `.url` корректно открывается как интернет-ярлык;
- [x] обычные файлы вроде `.txt` и `.pdf` открываются через зарегистрированное приложение Windows;
- [x] вложенные файлы `Workspace` также находятся, если их имя однозначно;
- [x] при реальной неоднозначности Jarvis показывает точные найденные пути;
- [x] пользователь может выбрать нужный вариант по номеру;
- [x] после выбора запускается именно выбранный файл;
- [x] поиск установленных приложений не смешивается с однозначным совпадением в `Workspace`;
- [x] sandbox-ограничения остаются без изменений;
- [x] добавлены регрессионные тесты на один файл, несколько файлов, выбор варианта и неверный номер.

## Отдельный тестовый сценарий: Steam

```text
Workspace/
└── Steam.lnk

Jarvis: "Запусти Steam"

Ожидание:
→ найден ровно один файл
→ Workspace/Steam.lnk
→ ярлык запускается
→ Jarvis сообщает об успешном запуске
```

При наличии нескольких файлов:

```text
Workspace/
├── Steam.lnk
└── Steam.exe

Jarvis: "Запусти Steam"
→ показываются оба точных пути
→ пользователь вводит 1 или 2
→ запускается выбранный файл
```
