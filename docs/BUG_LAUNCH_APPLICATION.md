# Баг: `launch_application` открывает не все файлы из `Workspace`

## Статус

**Не исправлено.**

## Описание

Jarvis должен уметь открывать файлы и ярлыки, находящиеся в его рабочей папке `Workspace`, по пользовательскому имени без обязательного указания расширения.

Сейчас часть файлов из `Workspace` не открывается корректно. В некоторых случаях вместо запуска единственного файла Jarvis сообщает, что найдено несколько вариантов приложения, хотя пользователь видит в `Workspace` только один соответствующий файл.

Пример:

```text
Workspace/
└── Steam.lnk
```

Команда:

```text
Запусти Steam
```

Ожидаемое поведение: `Steam.lnk` должен быть найден и открыт.

Фактическое поведение: Jarvis может сообщить о нескольких найденных вариантах приложения и не выполнить запуск.

## Требуемое поведение

`launch_application()` должен корректно открывать **любой разрешённый файл**, находящийся внутри `Workspace`, если пользователь однозначно указал его имя.

Минимально должны поддерживаться:

- `.lnk`;
- `.url`;
- `.exe`;
- `.bat`;
- `.cmd`;
- `.txt`;
- `.pdf`;
- другие файлы, которые Windows может открыть через зарегистрированное приложение.

Расширение не должно быть обязательным в пользовательской команде.

Примеры:

```text
Запусти Steam
→ Workspace/Steam.lnk

Открой DDNET
→ Workspace/DDNET.url

Открой text
→ Workspace/text.txt
```

## Важное ограничение безопасности

Поиск файлов для запуска должен оставаться ограниченным `Workspace`.

Нельзя исправлять баг путём разрешения произвольных путей за пределами sandbox.

## Текущая логика

`launch_application()` сначала пытается разрешить пользовательское имя через `resolve_tool_path()` и только после этого переходит к поиску установленных приложений через `find_application()`.

`find_by_name()` рекурсивно ищет файлы внутри `Workspace` и сопоставляет имя как с полным именем файла, так и с его `stem`.

Проблема требует проверить, почему при наличии одного файла в `Workspace` система иногда получает несколько совпадений либо почему управление передаётся в поиск установленных приложений.

## Что необходимо проверить

### 1. Реальное содержимое результатов поиска `Workspace`

При неоднозначности Jarvis должен возвращать точные пути всех найденных совпадений, а не только общее сообщение:

```text
Найдено несколько вариантов приложения.
```

Нужно видеть, какие именно файлы были найдены и откуда они взялись.

### 2. Рекурсивный поиск

Проверить наличие одноимённых файлов во вложенных каталогах `Workspace`.

Поиск должен учитывать всю разрешённую область `Workspace`, но не должен создавать ложные совпадения.

### 3. Сопоставление имени и расширения

Проверить случаи:

```text
Steam
Steam.lnk
Steam.url
Steam.exe
```

и определить однозначные правила выбора.

Если существует ровно один подходящий файл, запуск должен происходить без запроса выбора.

### 4. Разделение источников поиска

Нужно чётко различать:

```text
Workspace
```

и

```text
Установленные приложения Windows
```

Если файл найден в `Workspace`, поиск установленных приложений не должен создавать дополнительную неоднозначность.

Если неоднозначность действительно возникла среди установленных приложений, сообщение должно явно указывать, что совпадения найдены именно там.

### 5. Ярлыки Windows

Проверить `.lnk` и `.url` как самостоятельные запускаемые файлы.

Не следует требовать, чтобы имя ярлыка совпадало с именем реального `.exe`, если Windows может открыть сам ярлык через `os.startfile()`.

## Критерии готовности

Исправление считается завершённым, если:

- любой поддерживаемый файл из `Workspace` можно открыть по имени без расширения;
- единственный найденный файл всегда запускается без сообщения о нескольких вариантах;
- `.lnk` корректно открывается как ярлык Windows;
- `.url` корректно открывается как интернет-ярлык;
- обычные файлы вроде `.txt` и `.pdf` открываются через зарегистрированное приложение Windows;
- вложенные файлы `Workspace` также находятся, если их имя однозначно;
- при реальной неоднозначности Jarvis показывает точные найденные пути и позволяет выбрать нужный вариант;
- поиск установленных приложений не смешивается с однозначным совпадением в `Workspace`;
- sandbox-ограничения остаются без изменений.

## Отдельный тестовый сценарий: Steam

```text
Workspace/
└── Steam.lnk

Jarvis: "Запусти Steam"

Ожидание:
→ найден ровно один файл
→ Workspace/Steam.lnk
→ ярлык запускается
→ Jarvis сообщает об успешном запуске
```

Если система сообщает о нескольких вариантах, диагностика должна показать **точные пути всех совпадений**, чтобы было понятно, какой именно поиск породил ложную неоднозначность.
