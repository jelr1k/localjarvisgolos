# Статус реализации Jarvis

**Дата обновления:** 2026-09-15  
**Ветка:** `osnova`  
**Репозиторий:** `jelr1k/localjarvisgolos`

Документ отражает фактическое состояние кода ветки `osnova`, а не планируемое состояние.

## Реализовано

- [x] Автоматическое определение корня Jarvis и рабочего `Workspace` относительно расположения приложения.
- [x] Пользовательские настройки и алиасы в `%APPDATA%\\Jarvis`.
- [x] Sandbox и проверки путей перед файловыми операциями.
- [x] Файловые инструменты для поиска, чтения, создания и других поддерживаемых операций.
- [x] Безопасный запуск объектов из `Workspace` с поддержкой Windows-ярлыков.
- [x] Интерактивный выбор при нескольких совпадениях в `Workspace`.
- [x] Command Router для однозначных команд без обязательного обращения к LLM.
- [x] Ограниченный набор tools для конкретного запроса.
- [x] Multi-round Tool Calling с ограничением в 5 раундов.
- [x] Ollama Server и управление моделью из UI раздельно.
- [x] Освобождение модели при закрытии Jarvis при сохранении работающего Ollama Server.
- [x] Расширенное логирование Command Router, ToolExecutor, LLM/Ollama и управления процессами.
- [x] Unit/regression-тесты ключевых компонентов и GitHub Actions для тестов.
- [x] Локальный голосовой ввод через `faster-whisper`.
- [x] Голосовой ввод работает через существующий путь обработки сообщений: распознанный текст передаётся в ChatService/Command Router, отдельной логики выполнения голосовых команд нет.
- [x] Whisper загружается лениво при первом распознавании.
- [x] Текущая конфигурация Whisper: модель `small`, `cpu`, `int8`, язык `ru`, целевая частота дискретизации 16 kHz, `beam_size=5`, `vad_filter=True`.

## Не реализовано / в плане

- [ ] Wake word, по умолчанию `Jarvis`.
- [ ] Постоянный режим ожидания голосовой команды.
- [ ] TTS.
- [ ] Автоматический Model Router для выбора модели по сложности задачи.
- [ ] Финальная сборка и проверка `.exe`.
- [ ] Полная проверка установки зависимостей и переносимости конечной сборки.
- [ ] Расширенное покрытие сложных последовательностей Tool Calling.

## Известные проблемы

- [ ] **Поиск и разрешение имён файлов после голосового ввода.** В тесте с `test.txt` файл был создан в `Workspace` и успешно открывался по одной команде, но другие команды чтения/поиска сообщали, что тот же файл не существует. Требуется унифицировать поиск файлов для разных операций и всегда проверять фактическое содержимое `Workspace`.
- [ ] **Ошибки распознавания имён файлов Whisper.** Русские имена, латинские имена и расширения могут распознаваться неоднозначно (`test.txt` → `test.exe` и т. п.). Требуется слой нормализации/разрешения имени файла после STT, не позволяющий ошибке распознавания превращаться в ложное утверждение о существовании файла.
- [ ] **Ложные кандидаты файлов.** При проверке `Workspace` Jarvis не должен сообщать о файлах, которых физически нет. Список кандидатов должен формироваться только из фактического содержимого разрешённого `Workspace`.
- [ ] **Прокси в голосовом вводе.** В окружении пользователя `faster-whisper`/Hugging Face иногда получает `socks4://127.0.0.1:10808` от локального прокси Happ и выдаёт `Unknown scheme for proxy URL`. Проблема относится к сетевому окружению, а не к модели Whisper. Рабочий обход был проверен через очистку proxy-переменных для текущей CMD-сессии.

## Важное уточнение по голосовой подсистеме

Голосовой ввод сейчас не считается полностью завершённым только потому, что `faster-whisper` уже подключён. Распознавание текста работает, но качество разрешения имён файлов после STT требует отдельного исправления. Whisper должен отвечать только за преобразование аудио в текст; поиск реального файла и проверка его существования должны выполняться файловой подсистемой на основании фактического `Workspace`.
