# Jarvis — ТЗ автоматических алиасов

**Статус:** ПЛАН
**Основное ТЗ:** `docs/TZ_JARVIS_UNIFIED.md`
**Ветка:** `osnova`

## 1. Цель

Убрать необходимость вручную создавать базовые алиасы для каждого объекта, добавленного в `Workspace`.

При добавлении приложения, игры, ярлыка или другого запускаемого пользовательского объекта в `Workspace` Jarvis должен автоматически определить его отображаемое имя и сделать его доступным для поиска и запуска без ручного заполнения Alias Manager.

## 2. Автоматический базовый алиас

Для каждого нового объекта в `Workspace` Jarvis автоматически создаёт внутренние алиасы на основе имени объекта.

Примеры:

- `Steam.url` → `steam`;
- `Telegram.lnk` → `telegram`;
- `Geometry Dash.exe` → `geometry dash`;
- `Minecraft.lnk` → `minecraft`.

При этом расширение файла не должно быть обязательным для обращения к объекту.

Автоматический алиас должен обновляться или пересоздаваться при переименовании объекта и удаляться из индекса при удалении объекта.

## 3. Нормализация

При генерации автоматических алиасов необходимо учитывать:

- регистр букв;
- расширение файла;
- лишние пробелы;
- повторяющиеся пробелы;
- базовую пунктуацию;
- варианты имени без пробелов для коротких и однозначных названий, где это безопасно.

Пример:

`Geometry Dash.exe` → `geometry dash`, дополнительно допустимо `geometrydash`.

Нормализация не должна создавать большое количество ложных совпадений.

## 4. Русские автоматические алиасы

Jarvis должен по возможности автоматически создавать русские варианты для распространённых приложений и игр.

Целевой пример:

`Steam.url` →

- `steam`;
- `стим`.

`Telegram.lnk` →

- `telegram`;
- `телеграм`;
- при наличии устойчивого общеупотребительного варианта — соответствующий русский вариант.

`Minecraft.lnk` →

- `minecraft`;
- `майнкрафт`;
- допустимые распространённые сокращения, например `майн`, если механизм может подтвердить их однозначность.

### 4.1. Ограничения русских алиасов

Русские варианты нельзя генерировать простым переводом каждого английского названия: это часто приводит к неправильным или бессмысленным словам.

Приоритет источников:

1. встроенный словарь общеупотребительных названий приложений и игр;
2. безопасные правила транслитерации/фонетического соответствия, если результат достаточно надёжен;
3. пользовательские алиасы из Alias Manager;
4. интеллектуальная генерация как необязательное расширение, если её точность можно контролировать.

Ненадёжные варианты не должны автоматически становиться активными алиасами только ради увеличения количества совпадений.

## 5. Разделение автоматических и пользовательских алиасов

Внутренне необходимо различать:

- **автоматические алиасы** — создаются и обновляются Jarvis;
- **пользовательские алиасы** — добавляются пользователем вручную.

Пользовательские алиасы нельзя удалять или изменять автоматически при переименовании или пересканировании объекта.

Alias Manager должен визуально показывать обе категории отдельно.

Пример UI:

```text
Steam.url

Автоматические:
✓ steam
✓ стим

Пользовательские:
✓ моя помойка
+ Добавить алиас
```

## 6. Индекс Workspace

Jarvis должен поддерживать актуальный индекс объектов `Workspace`, связывающий объект с его автоматическими и пользовательскими алиасами.

После добавления объекта в `Workspace` он должен быть сразу доступен для поиска.

Индекс должен обновляться при:

- добавлении объекта;
- удалении объекта;
- переименовании;
- перемещении внутри `Workspace`;
- изменении пользовательских алиасов.

Источником истины для существования объекта остаётся фактическое содержимое `Workspace`, а не текст команды пользователя или результат STT.

## 7. Интеграция с Command Router

Поиск приложения по автоматическому алиасу должен выполняться без обязательного обращения к LLM.

Целевая схема:

```text
Пользовательская команда
        ↓
Command Router
        ↓
нормализация
        ↓
поиск по индексу Workspace
        ├─ точное совпадение → запуск
        ├─ одно уверенное похожее совпадение → запуск
        └─ несколько кандидатов → показать список и запросить номер
```

Простые команды вроде `открой стим`, `запусти телеграм` или `открой майнкрафт` не должны отправляться в LLM только ради определения приложения, если объект однозначно находится через индекс.

## 8. Неоднозначность и безопасность

Если несколько объектов соответствуют одному алиасу, Jarvis не должен выбирать случайный объект.

Например:

```text
Найдено несколько объектов:
1. Steam.url
2. Steam.exe
```

Jarvis должен показать кандидатов и принять номер выбора.

Автоматические алиасы не должны обходить существующую систему разрешений и ограничения `Workspace`.

## 9. Производительность

Генерация и поиск автоматических алиасов должны быть дешёвыми по ресурсам.

Для обычного поиска приложения не требуется запуск локальной LLM.

Предпочтительный механизм: нормализация строк + индекс + контролируемое нечёткое сопоставление.

## 10. Будущее расширение

В дальнейшем механизм может учитывать:

- распространённые русские названия;
- сокращения;
- ошибки распознавания Whisper/STT;
- морфологические формы русского языка;
- пользовательскую историю успешных команд.

При этом обучение на истории не должно молча создавать потенциально опасные или неоднозначные команды.

## 11. Критерии готовности

Функция считается реализованной, если:

- новый объект в `Workspace` автоматически получает базовый алиас;
- расширение файла не требуется в команде;
- автоматические алиасы отображаются в Alias Manager;
- пользовательские алиасы остаются отдельными;
- переименование объекта корректно обновляет автоматические алиасы;
- удаление объекта убирает его из индекса;
- несколько совпадений корректно обрабатываются через выбор пользователя;
- простая команда запуска не требует LLM при однозначном совпадении;
- для распространённых приложений поддерживаются русские алиасы;
- ненадёжные русские варианты не создаются автоматически без достаточной уверенности.
