# Bug: `close_application` не закрывает Prism Launcher

## Статус
- Тип: ошибка приложения
- Компонент: `tools/applications.py`
- Затронутые инструменты: `close_application`, потенциально `get_process_status`
- Пример: Prism Launcher
- Приоритет: высокий

## Как проявляется

Пользователь даёт Jarvis команду:

> Закрой Prism Launcher

Приложение сначала находит Prism Launcher через `find_application("Prism Launcher")` и получает путь к ярлыку:

```text
C:\Users\Jelr1k1\AppData\Roaming\Microsoft\Windows\Start Menu\Programs\Prism Launcher.lnk
```

После этого вызывается `close_application("Prism Launcher")`.

Инструмент сообщает:

```text
Процесс не запущен: Prism Launcher
```

При этом Prism Launcher фактически может быть запущен.

## Причина

`find_application()` и `close_application()` используют разные способы идентификации приложения.

`find_application(name)` ищет приложение как пользовательскую сущность и может вернуть путь к `.lnk` или `.exe`.

`close_application(name)` не использует результат `find_application()`. Вместо этого он напрямую вызывает `_running_process_matches(name)` и пытается найти процесс, имя или executable stem которого совпадает с переданной строкой.

Текущая логика фактически предполагает:

```text
название приложения = имя Windows-процесса
```

Это неверно как общее правило.

Например:

```text
Prism Launcher.lnk
        ↓
ярлык приложения
        ↓
target executable
        ↓
реальное имя процесса
```

Имя ярлыка `Prism Launcher` не обязано совпадать с именем `.exe` или процесса. Поэтому `_running_process_matches("Prism Launcher")` может не найти реально работающий Prism Launcher.

## Почему это проблема архитектуры

Ошибка не должна исправляться только через prompt или инструкцию для LLM вроде:

> Для Prism Launcher используй prismlauncher.exe.

Это будет частным обходным путём и не решит проблему с другими приложениями.

Инструментальный слой должен уметь преобразовывать идентичность приложения в идентичность процесса.

## Ожидаемое поведение

Для команды:

```text
Закрой Prism Launcher
```

Jarvis должен:

1. Найти приложение по пользовательскому имени.
2. Разрешить найденный `.lnk` в его реальный target.
3. Определить executable/process, относящийся к этому приложению.
4. Найти соответствующий запущенный процесс.
5. Корректно завершить его.
6. Проверить, что процесс действительно завершился.
7. Вернуть понятный результат пользователю.

Если приложение уже закрыто, желательно возвращать идемпотентный успешный результат вроде:

```text
Prism Launcher уже закрыт.
```

а не выдавать ошибку, будто инструмент сломан.

## Связанные проблемы

`get_process_status(name)` использует ту же `_running_process_matches(name)` напрямую, поэтому у него потенциально такая же проблема.

## Требуемое исправление

Создать общий слой разрешения:

```text
Application Resolver
        ↓
Application Identity
        ↓
Process Resolver
        ↓
Process Status / Close / Launch
```

Минимально необходимо:

- научиться читать target Windows `.lnk`;
- разрешать `application name → .lnk/.exe → target executable`;
- находить реальный процесс по resolved executable, а не только по отображаемому имени приложения;
- перевести `close_application` на новый resolver;
- перевести `get_process_status` на тот же resolver;
- после `terminate()` проверять фактическое завершение процесса;
- добавить тесты, где имя `.lnk` отличается от имени процесса;
- отдельно проверить Prism Launcher на Windows.

## Нежелательное решение

Не добавлять набор жёстко прописанных исключений вида:

```text
Prism Launcher → prismlauncher.exe
Discord → Discord.exe
...
```

если только это не используется как fallback после универсального resolver.

## Критерий готовности

Команда `Закрой Prism Launcher` должна корректно закрывать запущенный Prism Launcher независимо от того, что имя его ярлыка отличается от имени реального процесса. Jarvis также должен корректно сообщать состояние, если приложение уже закрыто.
