# Баг: закрытие приложения не работает при несовпадении имени ярлыка и процесса

## Статус

Не исправлен. Предыдущая попытка исправления не подтвердила устранение проблемы на реальной системе пользователя.

## Описание

При запуске приложения через ярлык имя объекта в Workspace может не совпадать с именем реально запущенного процесса Windows.

Пример с Telegram:

- ярлык в Workspace: `Telegram`
- реальный основной процесс: `Telegram Desktop`
- дочерний процесс может иметь другое имя

Само имя ярлыка не является надёжным идентификатором процесса.

## Наблюдаемое поведение

Команда вида `закрой Telegram` всё ещё может не закрывать уже запущенный Telegram, хотя приложение было запущено через соответствующий ярлык.

## Что известно

В `tools/applications.py` уже реализована попытка разрешать `.lnk` через `WScript.Shell` и использовать `TargetPath`, однако фактический результат на пользовательской системе не подтвердил, что этого достаточно.

Поэтому считать баг исправленным нельзя.

## Что требуется для следующего исправления

1. Использовать подробные логи `logs/` для фиксации всей цепочки:
   `команда -> Command Router -> alias -> Workspace -> .lnk -> TargetPath -> поиск процессов -> найденные PID -> PPID -> executable -> cmdline -> дерево -> terminate -> wait_procs`.
2. По логам определить, на каком именно этапе теряется связь `Telegram.lnk -> реальный процесс Telegram`.
3. Проверить фактические значения `TargetPath`, `exe`, `name`, `cmdline`, `ppid` и дерево процессов Telegram на ПК пользователя.
4. После этого выбрать конкретный механизм идентификации и только затем менять алгоритм закрытия.
5. Не считать совпадение имени процесса обязательным условием.
6. Не добавлять системные process-guards в рамках этого бага без отдельного требования.

## Диагностика

Для диагностики Jarvis теперь сохраняет расширенные логи. Особенно важны `logs/jarvis.log`, `logs/errors.log` и записи событий процесса, включая снимки процессов до и после попытки закрытия.

Это позволяет не гадать, почему Windows решила проявить характер, а увидеть фактическую цепочку поиска и закрытия.
