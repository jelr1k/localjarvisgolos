# Баг: закрытие приложения не работает при несовпадении имени ярлыка и процесса

## Статус

Исправлен.

## Описание

При запуске приложения через ярлык имя объекта в Workspace может не совпадать с именем реально запущенного процесса Windows.

Пример с Telegram:

- ярлык в Workspace: `Telegram`
- реальный основной процесс: `Telegram Desktop`
- дочерний процесс: имя пользователя Telegram, например `шпалтер консерва`

Само имя ярлыка не является надёжным идентификатором процесса, поэтому закрытие должно опираться на целевой исполняемый файл ярлыка, а не требовать совпадения отображаемых имён.

## Наблюдаемое поведение до исправления

Команда вида `закрой Telegram` могла не закрывать уже запущенный Telegram, хотя приложение было запущено через соответствующий ярлык.

## Причина

Старая логика могла сводить идентификацию к имени процесса. Для приложений с launcher-структурой или дочерними процессами это ненадёжно: имя ярлыка, имя основного процесса и имена дочерних процессов могут отличаться.

## Реализованное решение

В `tools/applications.py` идентификация приложения при закрытии теперь строится вокруг целевого executable:

1. `.lnk` разрешается через `WScript.Shell` в `TargetPath`.
2. Для объектов из Workspace путь ярлыка проверяется отдельно, даже если приложение отсутствует в Start Menu/PATH.
3. Целевой исполняемый файл сохраняется в `identity` как основной идентификатор приложения.
4. Поиск запущенного процесса сначала использует нормализованный полный путь к executable.
5. Если полный путь недоступен или отличается, используется имя целевого executable как резервная проверка.
6. Дополнительно проверяется командная строка процесса на наличие целевого executable.
7. Имя, введённое пользователем, используется для сопоставления процесса только когда целевой executable неизвестен. Таким образом, `Telegram` не становится обязательным именем процесса.
8. После нахождения корневого процесса Jarvis собирает всё дерево его дочерних процессов и завершает потомков перед корневым процессом.
9. После завершения используется `psutil.wait_procs()` для проверки фактического завершения.

Такой подход соответствует модели обычных Windows-инструментов управления процессами: идентификация должна опираться на PID/исполняемый файл, а дерево процессов обрабатываться отдельно. В Jarvis для этого остаётся `psutil`, без необходимости добавлять сторонние kernel-level механизмы.

## Почему решение работает для Telegram и аналогичных приложений

Команда `закрой Telegram` сначала разрешается в объект Workspace. Если это `Telegram.lnk`, Jarvis получает его `TargetPath` и использует именно этот executable для поиска процесса.

Поэтому отображаемое имя основного процесса (`Telegram Desktop`) и имена дочерних процессов больше не должны совпадать с названием ярлыка. После обнаружения основного процесса Jarvis закрывает его дерево.

При этом Jarvis не зависит от того, запускал ли он приложение сам: тот же механизм идентификации работает для уже запущенного пользователем приложения.

## Ограничения

- Совпадение имени процесса больше не является обязательным условием.
- Системные process-guards в рамках этого бага не добавлялись.
- Для приложений, которые полностью заменяют исходный launcher другим независимым процессом и не оставляют доступного целевого executable/связи в командной строке, может потребоваться отдельный механизм отслеживания запуска.

## Результат

Баг с несовпадением имени ярлыка и имени процесса устранён на уровне идентификации приложения. Основной идентификатор теперь целевой исполняемый файл ярлыка, а имя процесса используется только как резервный вариант при отсутствии такой информации.
