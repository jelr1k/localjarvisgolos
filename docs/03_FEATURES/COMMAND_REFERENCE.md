# Jarvis — справочник команд

**Статус:** рабочий справочник, который должен обновляться вместе с системой команд.

Этот документ описывает **все пользовательские действия Jarvis**, а не только команды, которые сейчас обрабатываются `Command Router` напрямую.

Здесь отдельно указывается, какой уровень обработки используется:

- **Router** — команда должна выполняться детерминированно, без запуска LLM.
- **LLM + Tools** — запрос передаётся локальной LLM, которая выбирает разрешённые инструменты.
- **Router + LLM** — Router определяет базовый сценарий/ограничения, а LLM нужна для сложной части задачи.
- **План** — возможность предусмотрена ТЗ, но ещё не считается реализованной.

> Этот файл является пользовательской шпаргалкой и одновременно каталогом поддерживаемых сценариев. Добавление новой пользовательской команды должно сопровождаться обновлением этого документа.

---

## 1. Управление приложениями

### Открытие / запуск

**Действие:** запускает приложение, игру, файл, папку или поддерживаемый объект Workspace.

**Тип:** Router.

**Примеры:**

```text
открой Steam
запусти Discord
включи Minecraft
вруби Telegram
```

**Основные варианты действия:**

- открой / открыть;
- запусти / запустить;
- включи / включить;
- стартуй / стартовать;
- запускай;
- вруби / врубить.

### Закрытие

**Действие:** закрывает приложение через процессную подсистему.

**Тип:** Router.

**Примеры:**

```text
закрой Steam
выключи Discord
заверши Telegram
останови Minecraft
```

**Основные варианты:**

- закрой / закрыть;
- останови / остановить;
- выключи / выключить;
- заверши / завершить;
- выруби / вырубить.

### Проверка состояния

**Действие:** проверяет состояние приложения/процесса.

**Тип:** Router.

**Примеры:**

```text
проверь Steam
проверь Discord
запущен ли Telegram
```

## 2. Работа с файлами и папками

### Поиск

**Действие:** ищет объект в Workspace.

**Тип:** Router.

**Примеры:**

```text
найди test.txt
где лежит config.json
покажи, где находится Steam
```

**Основные варианты:**

- найди / найти;
- поищи / поискать;
- отыщи / отыскать;
- разыщи / разыскать;
- покажи / показать;
- где находится;
- где лежит;
- расположение;
- местоположение.

### Чтение файла

**Действие:** получает фактическое содержимое файла.

**Тип:** Router.

**Примеры:**

```text
прочитай test.txt
прочти config.json
озвучь содержимое test.txt
```

**Основные варианты:**

- прочитай / прочесть / прочитать;
- прочти;
- зачитай / зачитать;
- озвучь / озвучить.

### Удаление

**Действие:** удаляет файл или папку с учётом действующих ограничений и разрешений.

**Тип:** Router.

**Примеры:**

```text
удали test.txt
сотри папку Test
убери old.txt
```

**Основные варианты:**

- удали / удалить;
- сотри / стереть;
- убери / убрать.

### Создание файла

**Действие:** создаёт файл.

**Текущее целевое поведение:** Router.

**Текущее состояние реализации:** инструмент `create_file` существует, но прямой маршрут Command Router должен быть отдельно доведён до полноценной поддержки.

**Примеры:**

```text
создай test.txt
создай файл config.txt
```

### Создание папки

**Действие:** создаёт папку.

**Текущее целевое поведение:** Router.

**Примеры:**

```text
создай папку Test
создай директорию Docs
```

### Запись / изменение содержимого

**Действие:** записывает указанный текст в существующий или созданный файл.

**Тип:** LLM + Tools для сложных формулировок; прямой Router-сценарий является целевым.

**Примеры:**

```text
запиши в test.txt Hello World
добавь в config.txt новую строку
замени содержимое test.txt на Hello
```

### Переименование

**Действие:** изменяет имя файла или папки.

**Тип:** LLM + Tools; прямой Router-сценарий является целевым.

**Примеры:**

```text
переименуй test.txt в hello.txt
назови папку Test как Documents
```

### Копирование

**Действие:** создаёт копию объекта в указанном месте.

**Тип:** LLM + Tools; прямой Router-сценарий является целевым.

**Примеры:**

```text
скопируй test.txt в Docs
сделай копию config.json
```

### Перемещение

**Действие:** перемещает объект.

**Тип:** LLM + Tools; прямой Router-сценарий является целевым.

**Примеры:**

```text
перемести test.txt в Docs
перенеси папку Test в Archive
```

### Информация об объекте

**Действие:** получает сведения о файле, папке или другом объекте.

**Тип:** LLM + Tools / целевой Router-сценарий.

**Примеры:**

```text
покажи информацию о test.txt
какой размер у config.json
```

### Поиск по содержимому

**Действие:** ищет текст внутри файлов.

**Тип:** LLM + Tools.

**Пример:**

```text
найди в файлах строку Hello World
```

## 3. Составные файловые задачи

Jarvis должен уметь обрабатывать задачи, состоящие из нескольких действий.

**Тип:** LLM + Tools.

**Примеры:**

```text
найди config.json, прочитай его и создай рядом копию
найди все txt-файлы и перемести их в папку Archive
создай файл, запиши в него текст и открой его
```

В таких сценариях Command Router не должен пытаться искусственно превратить сложную задачу в одну простую команду. Он передаёт её LLM с ограниченным набором разрешённых инструментов.

## 4. Ollama и локальная модель

### Проверка Ollama

**Тип:** Router.

Jarvis может напрямую обрабатывать команды управления состоянием Ollama Server.

### Запуск Ollama Server

**Тип:** Router.

### Остановка Ollama Server

**Тип:** Router.

### Управление моделью

Запуск/выгрузка модели и параметры генерации выполняются через соответствующую подсистему Jarvis и UI. Формулировки естественного языка для сложного управления моделью могут проходить через LLM, если для них нет отдельного Router-сценария.

---

## 5. CMD и PowerShell

**Статус:** планируемая возможность.

Jarvis должен поддерживать выполнение CMD/PowerShell-команд через контролируемые инструменты и Permission System.

Примеры будущих сценариев:

```text
выполни команду ipconfig
запусти PowerShell-команду ...
```

Для системных команд особенно важна отдельная система разрешений. LLM не должна самостоятельно получать права на выполнение произвольных команд.

---

## 6. Голосовые команды

Голосовой ввод не является отдельным набором действий. Whisper/STT преобразует голос в текст, после чего тот же текстовый Command Router/LLM pipeline обрабатывает команду.

Например:

```text
[голос] «Открой Steam»
        ↓
STT
        ↓
«Открой Steam»
        ↓
Command Router
        ↓
launch_application
```

Это означает, что добавление голосового ввода не должно требовать отдельной реализации каждой команды.

---

## 7. Общение с LLM

LLM используется не как универсальный исполнитель, а как уровень интерпретации сложных задач.

Она может:

- разбирать естественные и составные запросы;
- выбирать подходящие разрешённые tools;
- выполнять несколько последовательных tool calls;
- анализировать результаты инструментов;
- формировать итоговый ответ пользователю;
- выполнять сложные файловые сценарии;
- комбинировать несколько действий в одну задачу.

LLM не должна подменять детерминированные функции Router там, где команда однозначна.

## 9. Правило обновления справочника

При добавлении нового действия Jarvis необходимо обновить:

1. этот справочник;
2. список/регистрацию алиасов, если действие вызывается естественным языком;
3. Command Router, если действие должно выполняться детерминированно;
4. набор доступных tools, если действие выполняется LLM;
5. ТЗ и статус реализации, если изменение влияет на архитектуру или общий план проекта.

Таким образом, документация не должна расходиться с реальным набором возможностей Jarvis.
