# ТЗ: система алиасов и синонимов Jarvis

## 1. Зачем это нужно

Сейчас команда может правильно определить действие, но не всегда может найти нужный объект, если пользователь называет его не точным именем.

Пример:
- в `Workspace` находится `Prism Launcher`;
- пользователь говорит «открой Prism Launcher» → объект можно найти;
- пользователь говорит «открой Призм» или «открой Призму» → точного совпадения нет, поэтому приложение не находится.

То же относится к приложениям и командам:
- «открой Discord»;
- «открой дискорд»;
- «открой ДС»;
- «запусти DS».

Цель системы: Jarvis должен отделять **что сделать** от **с чем это сделать**, а пользовательские названия объектов должны настраиваться без изменения исходного кода.

## 2. Основная идея

Нужен отдельный слой `Alias Resolver` между распознаванием команды и выполнением действия.

Схема:

```text
Сообщение пользователя
        ↓
Command Router
        ↓
Определение действия
        ↓
Alias Resolver
        ↓
Поиск реального объекта
        ↓
Tool Executor
        ↓
Результат
```

LLM не должен быть единственным механизмом поиска точного имени файла или приложения. Его задача — понять намерение пользователя, а алиасы должны решать задачу сопоставления пользовательского названия с реальным объектом.

## 3. Два типа алиасов

### 3.1. Алиасы действий

Несколько формулировок означают одно действие.

Пример:

```text
открой
запусти
включи
запустить
открыть
```

→ `launch`

В дальнейшем это позволит не плодить отдельные regex под каждую формулировку.

### 3.2. Алиасы объектов

Несколько названий указывают на один объект.

Пример:

```text
Discord
дискорд
дс
ds
```

→ реальное приложение `Discord`

Или:

```text
Prism Launcher
prism
призм
призма
pl
```

→ реальное приложение `Prism Launcher`

Эта система должна быть применима не только к приложениям, но и к файлам, папкам и другим объектам, которые Jarvis сможет обрабатывать.

## 4. Хранение данных

Алиасы должны храниться отдельно от исходного кода и пользовательской логики.

Предпочтительный вариант:

```text
%APPDATA%\\Jarvis\\aliases.json
```

Пример структуры:

```json
{
  "applications": {
    "Discord": {
      "aliases": ["discord", "дискорд", "дс", "ds"]
    },
    "Prism Launcher": {
      "aliases": ["prism launcher", "prism", "призм", "призма", "pl"]
    }
  }
}
```

Важно: файл должен быть пользовательским конфигом, а не частью исходников проекта. Перенос или переименование папки Jarvis не должны ломать алиасы.

## 5. Интерфейс управления

В настройках Jarvis желательно добавить отдельный раздел `Алиасы` / `Названия`.

Пользователь должен иметь возможность:

- добавить приложение/объект;
- указать реальный объект;
- добавить несколько пользовательских названий;
- удалить алиас;
- изменить алиас;
- просмотреть существующие алиасы.

Пример интерфейса:

```text
Discord
  Реальное имя: Discord
  Алиасы:
    discord
    дискорд
    дс
    ds

Prism Launcher
  Реальное имя: Prism Launcher
  Алиасы:
    prism
    prism launcher
    призм
    призма
    pl
```

Редактирование должно происходить без ручного изменения JSON и без необходимости открывать код.

## 6. Автоматическое создание алиасов

При обнаружении приложения Jarvis может автоматически создать базовый набор алиасов из его реального имени.

Например:

```text
Prism Launcher
↓
prism launcher
prism
```

Но пользовательские сокращения и русские варианты нельзя бездумно угадывать и сохранять автоматически.

Желательный механизм обучения:

```text
Пользователь: «Открой Призм»

Jarvis: «Я нашёл Prism Launcher. Добавить “Призм” как название этого приложения?»

[Да] [Нет]
```

При подтверждении `призм` сохраняется как алиас Prism Launcher.

Это безопаснее полного автоматического обучения, потому что одинаковые или похожие слова могут соответствовать разным объектам.

## 7. Поиск по алиасу

Resolver должен:

1. нормализовать ввод пользователя;
2. проверить точное имя;
3. проверить алиасы;
4. при необходимости выполнить безопасный поиск похожего имени;
5. если найдено несколько кандидатов, не выбирать случайный объект молча;
6. при неоднозначности запросить уточнение или показать варианты.

Нормализация должна учитывать как минимум:

- регистр;
- лишние пробелы;
- базовые различия пунктуации;
- русские/английские варианты, если они явно указаны пользователем.

## 8. Важное разделение ответственности

Не следует превращать LLM в огромный словарь всех приложений пользователя.

Правильное разделение:

```text
LLM / Command Router
    ↓
«Нужно запустить приложение с названием “Призм”»
    ↓
Alias Resolver
    ↓
“Призм” → “Prism Launcher”
    ↓
Application Tool
    ↓
Запуск приложения
```

Так система будет предсказуемее, дешевле по вычислениям и проще для отладки.

## 9. Совместимость с текущим Command Router

Система алиасов должна стать отдельным сервисом/компонентом, который можно вызвать из существующего `services/command_router.py`.

Не нужно переписывать Command Router только ради алиасов.

Сначала реализовать Resolver и хранилище, затем подключить их к существующим операциям:

- запуск приложения;
- проверка статуса приложения;
- поиск файла;
- чтение файла;
- удаление файла;
- другие операции по мере появления.

## 10. Что не делать

Не делать:

- жёстко прописанные русские варианты в regex каждого действия;
- отдельную проверку `if name == ...` для каждого приложения;
- хранение пользовательских алиасов внутри Python-кода;
- передачу каждой простой команды в LLM только ради поиска имени;
- автоматическое сохранение любого случайного похожего слова без подтверждения пользователя.

## 11. Этапы реализации

### Этап 1

Создать `AliasManager` / `AliasResolver` и JSON-хранилище в `%APPDATA%\\Jarvis\\aliases.json`.

### Этап 2

Добавить нормализацию и поиск по точному имени + алиасу.

### Этап 3

Подключить алиасы к приложениям.

Минимальные тесты:

```text
«открой Discord»
«открой дискорд»
«открой ДС»
«открой DS»
```

Все варианты должны приводить к одному приложению.

### Этап 4

Подключить алиасы к файлам и папкам.

### Этап 5

Добавить GUI управления алиасами в настройки.

### Этап 6

Добавить предложение сохранить новый алиас при успешном fuzzy-match.

### Этап 7

Покрыть Resolver тестами и проверить поведение при неоднозначных совпадениях.

## 12. Критерий готовности

Система считается базово готовой, если пользователь может без изменения кода настроить несколько названий одного приложения и затем использовать любое из них в команде.

Например:

```text
«Открой Discord»
«Открой дискорд»
«Открой ДС»
«Запусти DS»
```

и

```text
«Открой Prism Launcher»
«Открой Prism»
«Открой Призм»
«Открой Призму»
```

должны приводить к одному и тому же целевому приложению.

## Короткая версия для разработчика

**Проблема:** Command Router понимает действие, но точное имя объекта сейчас слишком сильно зависит от совпадения с реальным именем.

**Решение:** добавить отдельный `Alias Resolver` с пользовательским хранилищем `%APPDATA%\\Jarvis\\aliases.json`.

**Главное правило:** действие и объект должны обрабатываться отдельно. LLM/Router определяет намерение, Resolver сопоставляет пользовательское название с реальным объектом, Tool Executor выполняет действие.

**Приоритет реализации:** `AliasManager → JSON storage → normalization → application aliases → GUI → optional confirmed learning → files/folders → tests`.

**Пользователь не должен редактировать код или JSON вручную.**
